# EVAL — scripted and recorded, side by side

Two results sources, two columns per batch, never one instead of the other (D-23).

- **Scripted — a plumbing check, not a measurement.** `tools/scripted_model.py`, a designed error model written by the pipeline's author, replayed through the TypeScript pipeline. It proves the screen, parser, policy, cost, drift and scoring arithmetic reproduce the Python oracle exactly; it says nothing about any model. Token counts are estimates.
- **Recorded — the first real measurement.** Real Message Batches responses from `claude-haiku-5-5` (tier A) and `claude-sonnet-5-5` (tier B), recorded 2026-10-25 and replayed from `recordings/` (D-49). Judge: the answer key `tools/build_fixtures.py` wrote for synthetic tickets, by the same author. These numbers measure two models on 1,200 synthetic tickets against that key; they are not a claim about a production inbox. Tokens and cost are from the usage fields.

Both columns: policy v1, T = 7500, fixtures seed 20261019, 2026-10-27 (after D-51's straddle rule; the recordings' `decisions.jsonl` were regenerated by replay, the tier files are untouched).

- Scripted: `npm run -s triage:eval 2>/dev/null`; stdout byte-identical to `fixtures/samples/reference_pipeline.output.txt`; stderr `per-ticket decisions: 1200 of 1200 equal to fixtures/decisions_batch{1,2}.csv`; exit 0. Spend $0.
- Recorded: `npm run -s triage:eval -- --provider recorded 2>/dev/null`; stderr `per-ticket decisions: 1200 of 1200 equal to recordings/batch{1,2}/decisions.jsonl`; exit 0. CI runs both with no key. Spend to date **127¢** of the 1500¢ project cap (ledger `data/runs.jsonl`: 4¢ first run, `INCOMPLETE` at tier B under the 300¢ cap, D-48 · 46¢ batch 1 · 40¢ batch 2 · 25¢ + 12¢ tier-B top-ups for the sweep, D-50).

## The gate
