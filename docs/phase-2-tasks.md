- [x] **2.1 SDK, with a decision.** *Done 2026-10-21 (D-41).* Add `@anthropic-ai/sdk` as the only runtime dependency (D-3), with a `docs/decisions.md` entry that names the exact version. Import it only under `src/providers/`; `policy:lint` already forbids `anthropic` under `src/pipeline/`. *Acceptance:* `npm ci` is clean, `policy:lint` OK, and a test proves `src/pipeline/` still imports nothing new.
- [x] **2.2 `live` provider (Batches).** *Done 2026-10-21 (D-42).* `client.messages.batches.create({requests: [{custom_id, params}]})`, then poll `retrieve(id).processing_status` until `"ended"`, then stream `results(id)`. Key results by `custom_id`, because they come back in any order. Params:
  - System is one text block with `cache_control: {type: "ephemeral", ttl: "1h"}` (O-7). The schema goes in `output_config.format`.
  - No prefill, no sampling params, no `budget_tokens`; each one is a 400 on the 5.5 models. Set `output_config.effort` explicitly (proposed: `low`), because thinking is on by default on Haiku 5.5 and Sonnet 5.5 and its tokens bill as output. Record the effort decision.
  - The server-side `fallbacks` parameter is rejected on Batches. A `stop_reason: "refusal"` result is a typed failure (`PARSE_REFUSAL` or similar, D-8), never a label.
  - Before submitting, assert that the system and schema bytes are identical across every request in the batch (non-negotiable 8).

  *Acceptance:* a unit test against a fake client, which is never the network, checks the request shape, the byte-identity assert and every `result.type` (`succeeded`/`errored`/`canceled`/`expired`). The provider refuses without `TRIAGE_LIVE=1` and a key.
- [x] **2.3 Projection and the two caps.** *Done 2026-10-22 (D-43).* Before submit, project the cost: estimated tokens × price, assuming the cache misses, plus a stated thinking-token allowance. Refuse if the projection exceeds `TRIAGE_RUN_CAP_CENTS` or what is left of `TRIAGE_PROJECT_CAP_CENTS` over the ledger. After results, sum the real cost from the usage fields. Over the cap, the ledger row is marked `OVER_CAP` and further live runs are refused until `--acknowledge-over-cap` (D-19). No flag removes a cap. *Acceptance:* tests cover refused-by-projection, the latch, the acknowledgement and the project cap across rows.
- [x] **2.4 Usage → cost, real kinds.** Map `usage.input_tokens`, `cache_read_input_tokens`, `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` and `output_tokens` into the existing normalised `Usage` (D-32). Price at batch rates. An unknown model id throws. *Acceptance:* a GC-style test on a hand-written usage object; a mutant pricing 1h writes as 5m fails it.
