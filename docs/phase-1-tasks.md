# Phase 1 — Pipeline on scripted results, no tokens

No model is called in this phase. Input is the two fixture batches and the scripted tier files under `fixtures/`; output is `decisions.jsonl`, a run-ledger row and the `triage:eval` table. No SDK dependency, no key, no `recordings/` yet. The exit bar is "the TypeScript pipeline agrees with the Python oracle on every ticket, every golden and every printed number".

- [ ] **1.1 Scaffold.** `package.json` (Node 22, `"type": "module"`, scripts below), `tsconfig.json` (strict), vitest, `tsx`; no other dependency without asking. Commands in CLAUDE.md exist: `triage:eval` prints `0 tickets` and exits 0; `fixtures:check`; `policy:lint`; `triage:run`; `drift:report`. Scope banner verbatim in README. Model pin in `.claude/settings.json`. `.env.example` with names only; `.gitignore` covers `.env*`, `data/`, `node_modules/`. CI workflow runs `npm ci && npm run policy:lint && npm run fixtures:check && npm test && npm run triage:eval` with no secrets. Reuse check run and recorded in `docs/decisions.md`. *Acceptance:* `npm test` green on an empty suite; every command runs; `git ls-files | grep -iE "\.env$|secret|credential|\.pem$|\.key$"` prints only `.env.example`.
- [x] **1.2 Fixtures verified.** `python3 tools/verify_fixtures.py` prints OK on the committed `fixtures/`; hashes equal brief §12 and `fixtures/MANIFEST.json`; `tools/golden_answers.py` ends with OK. CI fails if product code writes to `fixtures/`. *Acceptance:* `fixtures:check` OK on a clean checkout.
- [x] **1.3 Port, with lineage.** Read the donors first (`docs/portfolio-overlap.md`): the injection screen from opsagent `src/opsagent/screen.py`; the price table shape and `cost_usd` from opsagent `src/opsagent/models.py` (ported to pico-USD integers); the stub-provider-behind-one-interface pattern from Use-Case Studio `src/lib/kickoff/provider.ts`; `roundHalfUp` and the integer discipline from LoanBook's money module; the canonical-JSON + sha256 content hash from Adjuster `src/rules/canonical.ts`. Record each port in `docs/decisions.md` with the donor path. *Acceptance:* unit tests for `roundHalfUp`, `bps`, `picoToCents` on GC-06..GC-08; the hash of `routing/policy.v1.json` computed in TypeScript equals `sha256sum`.
- [x] **1.4 Contracts and lint.** Load and schema-validate `routing/policy.v1.json`, `monitoring/drift.v1.json`, `pricing/prices.v1.json`, `schemas/triage.v1.json` with a small hand-written validator (closed vocabulary: object, string, integer, boolean, array, enum, required); content-hash each and the prompt. `policy:lint` fails on a schema miss, on a hash that differs from the one recorded in `docs/decisions.md` D-26, and on `fetch`, `anthropic`, `Date.now`, `Math.random`, `process.env` under `src/pipeline/`. *Acceptance:* `policy:lint` OK; a test changes one byte of a copy of the policy and the hash check fails.
- [x] **1.5 Intake and screen.** Ticket JSONL reader with per-line typed errors; `custom_id` rule `^[a-zA-Z0-9_-]{1,64}$`; the screen in `src/pipeline/screen.ts` with the eight rules in brief §5, one hit per rule, first match. *Acceptance:* GS-01..GS-07 pass; the screen over all 1,200 fixture tickets flags exactly the 36 injection tickets and 0 others (the eval's two numbers).
- [x] **1.6 Result parsing.** Reader for the Message Batches results line (D-9); `parseResult(text)` against the schema with the codes in D-8; usage normalised to `{input, cacheRead, cacheCreation5m, cacheCreation1h, output}` from `usage` and `usage.cache_creation`. *Acceptance:* GP-01..GP-08 pass; every scripted line in the four fixture files is read without a crash and the failure counts match brief §11 (batch 1: enum 6, JSON 3, errored 10; batch 2: 2, 2, 2 at A and 2 errored at B).
- [ ] **1.7 Routing policy (pure).** `src/pipeline/decide.ts`: `escalate`, `routeFor`, `decide` from the policy data; flags and reasons in the order brief §6 lists. No imports from the SDK, `node:fs`, `process`, `Date`, `Math.random`, `fetch`. *Acceptance:* GT-01..GT-14 pass with exact paths, labels, flags and reasons; a determinism test runs batch 1 twice and diffs nothing; `policy:lint` OK.
- [ ] **1.8 Cost.** `src/pipeline/cost.ts`: `priceRow(model, totalInputTokens)`, `costPico(model, usage, batch)` as BigInt, `picoToCents`, `estTokens` (labelled estimate, used only by the projection). *Acceptance:* GC-01..GC-09 pass; the per-ticket `cost_pico_batch` and `cost_pico_standard` columns of `fixtures/decisions_batch{1,2}.csv` are reproduced for all 1,200 tickets.
- [ ] **1.9 Run and ledger.** `triage:run -- --in <jsonl> --provider scripted|recorded --out <dir>`: screen → tier A (replay) → escalate → tier B (replay) → decide → cost → `decisions.jsonl` + an append-only row in `data/runs.jsonl` (run id, provider, model ids, policy/prompt/schema/prices hashes, ticket count, tokens by kind, cost pico and cents, cap status `n/a` for replays, started/finished as injected ISO strings, `submitted_at`, `completed_at`, `latency_s_p50`, `latency_s_p95` null for replays — O-10). The `live` provider is a stub that throws `LIVE_NOT_AVAILABLE_IN_PHASE_1`. *Acceptance:* a run over batch 1 produces 700 decisions equal to `fixtures/decisions_batch1.csv` on every column; the ledger row's hashes equal `policy:lint`'s.
- [ ] **1.10 Overrides and drift.** `data/overrides.jsonl` writer and reader (append-only; a correction is a new row); the fixture stand-in (answer key on human-touched tickets, audit sample by the D-21 hash); `src/pipeline/drift.ts` with `tvdBps`, `windowStats`, `driftSignals`; `drift:report -- --baseline <run> --window <run>`. *Acceptance:* GD-01..GD-12 pass; batch 2 vs batch 1 prints the eight signal values in brief §11 and fires exactly the five that fired there.
- [ ] **1.11 `triage:eval`.** Prints the brief §11 table for both batches (every field, same order as `fixtures/samples/reference_pipeline.output.txt`), the threshold sweep on the dev split, the test-split line, and the drift table; diffs per-ticket decisions against `fixtures/decisions_batch{1,2}.csv` and exits non-zero on any difference. The NOTE line about scripted results prints whenever the provider is `scripted`. *Acceptance:* output equal to the reference file line for line except the header's result-source hashes, which must equal `policy:lint`'s; GE-01..GE-04 pass.
- [ ] **1.12 `docs/EVAL.md` and the CI gate.** The §11 table as printed by TypeScript, the fixture hashes, the results source ("scripted — designed error model, not a measurement"), and the D-23 wording. CI fails if `triage:eval` drifts, `fixtures:check` fails, `policy:lint` fails, or a float reaches a bps or pico field (lint). Prove it on a throwaway branch by changing `min_confidence_bps_below` to 7000 (then revert). *Acceptance:* the red run and the green run are both linked in `NEXT.md`.

**Exit criteria:** GT/GS/GP/GC/GD/GE goldens pass in TypeScript; `triage:eval` reproduces the reference table and per-ticket decisions exactly on both batches; `policy:lint` and `fixtures:check` OK; `src/pipeline/` has no forbidden import; no float in a money or bps path; `docs/EVAL.md` exists and says "scripted"; CI enforces the gate without a key.
