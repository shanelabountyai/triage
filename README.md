# Triage — High-Volume Support Ticket Triage Pipeline

Build Log A5 (AI track). An LLM as a production pipeline step at volume instead of one call per click: inbound support tickets for a fictional SaaS in, four labels out (category, priority, route, needs_human) through the Message Batches API with a cached prefix; a cheap model for every ticket and a stronger one for the uncertain ones with the escalation rule as data; cost per ticket from the API's usage fields under a hard cap; every test on recorded responses; drift monitoring over the label mix, the escalation share and the human-override rate.

## ⚠️ Scope Honesty (read first)

Learning project, synthetic data only. Fernwick is not a real company; every ticket, customer, name and email is generated by `tools/build_fixtures.py` from a seed; emails use `example.*` documentation domains. No real support inbox is ever loaded. The injection strings inside tickets are the author's own and the screen that catches them was written with that set in view, so its flag rate on the fixtures is an upper bound, not a measurement. Until Phase 2 records real responses, every number the eval prints comes from `tools/scripted_model.py`, a designed error model: those numbers test the plumbing and the arithmetic, not any model. Model ids and prices are read from Anthropic's docs on a stated date and may change; the pipeline never guesses a price. Nothing here is a claim about what an LLM triage system achieves in production; screens and write-ups report what was measured against the answer key, never "accurate" without the number. Banner verbatim in the README.

## Commands (npm; none calls the Claude API)

```
npm test                 # vitest; no network, no key
npm run triage:eval      # both fixture batches through the pipeline; prints the brief section 11 report; exits 1 on any per-ticket difference
npm run triage:run -- --in <jsonl> --provider <scripted|recorded|live> --out <dir>   # one run: decisions.jsonl, run.json, a row in data/runs.jsonl; live refuses before Phase 2
npm run drift:report -- --baseline <run dir> --window <run dir> [--overrides <path>] # the eight signals and which fired
npm run overrides:standin -- --run <run dir> --key <answer key csv>                  # fixtures only: the answer key as the reviewer (O-6)
npm run fixtures:check   # python3 tools/verify_fixtures.py && golden_answers.py && fixtures/ unchanged in git
npm run policy:lint      # schema-validates the data files, checks the D-26 hashes, purity and float lint over src/pipeline/
```
